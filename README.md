# Эмулятор командной оболочки ОС (Вариант №8)

Проект разработан в рамках дисциплины «Конфигурационное управление» (РТУ МИРЭА, преподаватель П.Н. Советов).

Вариант №8: Эмулятор командной строки UNIX-подобной операционной системы.  
Текущее состояние: **Этап 2 (Конфигурация и запуск)**.

---

## 1. Общее описание (Этап 2: Конфигурация и запуск)

На втором этапе реализована система конфигурации параметров запуска и поддержка пакетного выполнения скриптов:
- Загрузка параметров конфигурации через аргументы командной строки:
  - `--vfs`, `-v` `<путь>`: путь к архиву виртуальной файловой системы;
  - `--script`, `-s` `<путь>`: путь к стартовому скрипту.
- Отладочная команда `conf-dump`: вывод всех параметров текущей конфигурации в формате `ключ: значение`.
- При старте эмулятора выполняется стартовый скрипт с выводом выполняемых команд и их результатов в окно приложения.
- Результат работы стартового скрипта выдаётся на экран перед тем, как пользователь сможет вводить свои команды (поле ввода блокируется на время выполнения скрипта).
- Поддержка запуска скрипта как из файла на старте (`--script`), так и через интерактивный ввод пользователя (`source <файл>` / `run-script <файл>`).
- Разработаны сценарии демонстрации стартового скрипта:
  - штатный запуск (`emulator_scripts/stage2_demo.txt`);
  - ошибка: файл скрипта не существует;
  - синтаксическая ошибка в скрипте (`emulator_scripts/script_syntax_error.txt`).
- Написан проверочный bash-скрипт ОС (`os_scripts/test_cli_args.sh`) для автоматической проверки параметров CLI и сценариев скриптов.

## 2. Описание команд и параметров запуска

### Параметры командной строки
```bash
./run.sh --vfs <путь_к_vfs> --script <путь_к_скрипту>
# или с короткими флагами:
./run.sh -v <путь_к_vfs> -s <путь_к_скрипту>
```

### Поддерживаемые команды эмулятора
1. **`conf-dump`** — отладочная команда, выводит все параметры конфигурации:
   - `vfs_path`: путь к архиву VFS
   - `script_path`: путь к стартовому скрипту
   - `username`: имя текущего пользователя
   - `hostname`: имя компьютера
2. **`source <путь>`** (а также `run-script <путь>`) — выполняет скрипт построчно из интерактивного ввода пользователя.
3. **`ls [аргументы...]`** — команда-заглушка, выводящая имя команды и параметры.
4. **`cd [аргументы...]`** — команда-заглушка, выводящая имя команды и путь.
5. **`exit`** — завершает работу эмулятора и закрывает окно.

## 3. Команды для сборки и запуска тестов

- Запуск всех unit-тестов (Этап 1 + Этап 2):
  ```bash
  make test
  ```
- Проверка параметров командной строки и скриптов:
  ```bash
  make test-cli
  # или: bash os_scripts/test_cli_args.sh
  ```
- Проверка соответствия стандартам оформления кода (критерии П.Н. Советова):
  ```bash
  make lint
  ```
- Полная автоматическая проверка (стиль + unit-тесты + CLI-скрипты):
  ```bash
  make check
  ```
- Запуск приложения со стартовым скриптом Этапа 2:
  ```bash
  make run
  ```

## 4. Демонстрационные сценарии работы скрипта

1. **Штатный запуск (`stage2_demo.txt`):**
   ```text
   conf-dump
   ls /var/log
   cd $HOME
   exit
   ```
2. **Файл скрипта не существует:**
   Эмулятор выводит диагностическое сообщение `[ERROR] Стартовый скрипт не найден: ...` и переходит в режим ожидания команд пользователя.
3. **Синтаксическая ошибка в скрипте (`script_syntax_error.txt`):**
   При наличии синтаксической ошибки (например, ведущего пробела перед командой) выполнение скрипта немедленно прерывается с кодом ошибки и пояснением, после чего управление возвращается пользователю.
